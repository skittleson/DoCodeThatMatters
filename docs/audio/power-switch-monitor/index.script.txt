So, the biggest rule for home automation is not to change the existing behavior of users in a way that causes inconvenience or frustration. It’s a rule that gets easily forgotten. Let’s use the classic example of a smart light bulb in a living room. A user typically flips a switch to turn on and off a light. But now, with a smart bulb, they have to ask Alexa, Google, or use an app on their phone. That is bad.

I imagine you’ve seen those funny videos where people try to work around this problem. It’s causing a real inconvenience because the user can’t simply flip a switch anymore.

So, what are the solutions?

There are two common solutions usually presented in this situation. First, there is blocking the user. You might cover the switch with tape or another mechanism. You can actually see how common this is on websites like Thingiverse, where people share 3D prints for light switch covers. But this changes user behavior, so it’s a bad idea.

Second, you can replace the light switch with a smarter one. This is often considered the best option, but it requires a hardware replacement of the physical light switch. That may not be possible, it can be costly, and it’s potentially dangerous to attempt as a do-it-yourself project.

Then there is a third hybrid solution: triggering the smart device with the existing light switch using the power wall outlet as feedback. This uses an Arduino device with WiFi. In this setup, the light switch changes the power state of the outlet that the Arduino-based microcontroller is monitoring. When the light switch is turned on or off, it changes the power to the Arduino’s analog voltage GPIO pin. That sends a message off to your home assistance software to notify the smart device. In US-based homes, the second wall outlet still has power, so it provides constant power to the device.

There is a diagram in the blog post that illustrates the flow to toggle the smart bulb state from a user. It shows how the signal travels from the switch to the monitoring device and then to the smart bulb.

The advantages of this approach are quite compelling. First, it is simple and requires low effort. Second, you can use your existing switches to make them smart without replacing them. Third, you have the ability to control multiple devices with a single switch. And finally, the solution is open source.

Now, let’s talk about building the device.

Step one is getting the components and soldering them together. For tools, you will need a soldering iron and either a third hand or a vise to hold your parts steady.

As for materials, you’ll need a Wemos D1 Mini or a similar ESP8266 or ESP32 device. This acts as the WiFi microcontroller that reads the power state. You can find these on Amazon or other electronics retailers. You will also need two resistors; any two usually work, though I used 10-kilo-ohm ones. These create a voltage divider for the power sense pin. Optionally, you can add a BME280 or BME680 sensor for temperature and humidity sensing, which are also available on Amazon.

You will also need other materials like wire, solder, an LED, two 5-volt USB wall chargers, one male USB plug-in, and one regular USB charging cable for the ESP32.

The blog post includes several images here. One shows a breadboard version of the setup, so you can see how the components are arranged before soldering. Another image shows the schematic version, which is the technical diagram of the circuit. There are also photos showing the front and back of the Wemos Mini D1 Lite with the BME680 sensor attached, giving you a clear view of what the finished soldered device looks like from both sides.

Step two is downloading and uploading the software. You need to flash your device with Tasmota firmware. You can find the documentation for Tasmota online if you are unfamiliar with it.

For the Tasmota module configuration, you should set it to "Generic Module" and then click Save. The device will restart. Then you need to configure the pins. Pin D2 is used for I2C SDA, which connects to the BME680 sensor. Pin D1 is used for I2C SCL, also connecting to the BME680. And pin A0 is the analog pin that connects to the 5-volt power supply through the resistor divider.

Next, you need to set up the rules in the Tasmota console. When the external light switch power is on, we want to send a value of one. You will use a rule command that checks if the analog reading on pin A0 is greater than 1000. If it is, it performs a backlog of commands: it disables Rule1, enables Rule2, and publishes a message to the MQTT topic "cmnd/masterlight/SWITCH" with the value 1. It then ends the rule.

When the external light switch power is off, we want to send a value of zero. So you set up a second rule that triggers when the analog reading on pin A0 is less than 1000. When this happens, it enables Rule1, disables Rule2, and publishes a message to "cmnd/masterlight/SWITCH" with the value 0.

After setting these up, you enable Rule1 by typing "Rule1 1". Ensure that MQTT is enabled on your device. Then you can look at the console to verify it’s working. You should see messages similar to this log. The log shows timestamps and MQTT status updates. It displays entries like "stat/tasmota" followed by the power state turning on, then a rule performing actions, including delays and switching states. You will see the device publishing messages to the "cmnd/garagedoor/SWITCH" topic with values of 0 or 1, confirming that the power state is being read and translated into control signals. You’ll also see telemetry data being sent, such as uptime, memory usage, Wi-Fi signal strength, and current sensor states.

The MQTT topic used for control is "cmnd/masterlight/SWITCH", with a boolean value of either 1 for open or on, and 0 for close or off. The topics for state or the reed switch sensor value are sent every five minutes, which is configurable, via MQTT.

Step three is adding this to your home assistance system. This part can vary based on user preferences. I am using Node-Red, but this could be done with other home automation software like Home Assistant. The goal is to get the MQTT message from the Arduino and then process whatever notifications or actions you want to trigger.

The blog post includes a screenshot of the Node-Red power monitor setup. It shows the flow where it receives the MQTT input and routes it to the appropriate output nodes to control your smart devices.
