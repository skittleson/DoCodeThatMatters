So, have you ever had your central air conditioning unit shut off completely out of the blue? If you are a homeowner, I know this is a huge source of annoyance. It is actually the most common reason people call in a professional for service. The culprit is almost always that the air conditioner condensate drain line has become blocked. The solution is simple: you need to clean that drain line every single month by pouring a quarter cup of vinegar through it and then flushing it with water. But here is the catch—you have to remember to do it, and honestly, it is so easy to forget. Ideally, you should be doing this even more frequently to prevent any mold or bacteria buildup. This post is a guide on how to configure an off-the-shelf smart Wi-Fi dual water pump to flush out this line on a regular basis for you.

Let’s look at the plan. First, we will flash the device with Tasmota firmware. Second, we will set up a water reservoir. Third, we will route the water line to the AC condensate drain line opening, which is usually located near the start of the heating or fan unit. And finally, we will add rules to manage the water pump timing and send us notifications.

Now, for preparing the water pump, I ordered a Wi-Fi dual water pump from Amazon and flashed it using a guide I found online. You can find the link to that specific guide on the blog post. The only tricky part was soldering wires to those tiny connections shown in the guide’s image. I followed the traces on the board for two of them and soldered onto those instead, which gave me a bit more room to work with.

We need a few components here. The main one is that Wi-Fi dual water pump, specifically the model WD-01ADE, which does the actual flushing of the condensate line on a schedule. You can find it on Amazon.

I flashed the device using Tasmotizer, which is an open-source tool you can download from GitHub. After sending the Wi-Fi configuration, you grab the IP address. At this point, make sure to set the template defined in the guide by going to the Configuration menu and then selecting Configure Other. There is a specific code snippet for this template in the blog post that you need to copy and paste there. It defines the GPIO pins for the device so Tasmota knows how to talk to it.

In order to monitor the pump activations, I added a counter. This is really useful to keep track of how much water or vinegar mixture is left in the reservoir. You need to set this up after the template is applied by going to Configuration, then Configure Template. There, change GPIO 16 to Counter, and select Counter 1 from the drop-down menu. The good news is that this value is stored even after a reboot.

Next, let’s set up the water reservoir. I took a plastic bottle intended for vinegar and poked a hole in it about the size of the pump fitting. After that, I hot-glued one of the fittings that came with the water pump into that hole. Be sure to poke another hole in the top of the bottle so air can enter; otherwise, it will just create a vacuum and stop flowing.

There is an image on the blog post showing this setup. It depicts the plastic bottle with the hot-glued fitting installed, illustrating exactly how the connection looks before you hook it up to the pump.

Moving on to the Tasmota rules. We want to add a rule that triggers when the first pump has started. This rule will schedule the pump to turn off in 30 seconds, which should disperse about one cup of the vinegar and water mixture. It also increments Counter 1 by one. There is a specific command in the blog post that you need to copy and paste to set this up. It starts with "Rule 1 on power 1 state equals 1" and handles the timer and counter logic. You also need to turn this rule on.

We also want the pump to turn on every day at 4:00 AM, within a 15-minute window. There is another command in the post that configures Timer 1 with this schedule for all days of the week. Make sure to turn the Timers on as well.

You should also set the timezone of your location. In my example, I used minus eight, but you will want to adjust that to match where you live.

Lastly, if the device restarts, we need to ensure the water pump relays are off by default. This is not the default behavior with Tasmota firmware, so we have to explicitly tell it to keep power off on boot. There is a simple command in the post for this called PowerOnState set to zero.

If you want to see all of these commands together, there is a consolidated block of code in the blog post that you can copy directly. It also includes a link to an external script resource if you prefer that format.

Once you are done, the final results in the web interface look quite nice. There is a screenshot on the blog post showing the Tasmota WebUI. It displays the device status, the current counter value, and the configured timers, giving you a clear view of everything working together.

You can also see the MQTT sensor topic in action. The data looks something like this: it shows the timestamp and the current count for Counter 1, which in my case was at three. This confirms that the system is logging each cycle.

For future improvements, based on that counter, I plan to send an alert to remind me to refill the reservoir tank when it gets low.

If you want to dive deeper, there are several resources listed in the blog post, including the specific device template guide, a great article from Blair’s Air on how to unclog AC lines manually, the GitHub repository for Tasmotizer, the official Tasmota Device Manager documentation, and the docs for the PowerOnState command.
