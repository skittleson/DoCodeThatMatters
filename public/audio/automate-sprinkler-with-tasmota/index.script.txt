A simple water sprinkler system, for makers

Homeowners often find that over-the-shelf sprinkler systems can be difficult to use and lack customization options. They may also be outdated and may not be as efficient for water or power usage as desired. The "set it and forget" mentality is not always the best approach. It may be worth considering more customizable and efficient options for your home's sprinkler system.

Project Research

Want to improve your home's sprinkler system without breaking the bank? One solution is to use a combination of inexpensive hardware and customizable open-source software. This approach allows for flexibility and the ability to add additional features as needed. The main goal is to trigger the water sprinkler solenoid to turn on or off based on specific conditions such as time, including sunrise and sunset, humidity, and temperature. By implementing this method, you can achieve better results with low effort.

I should mention that there are affiliate links on this page for hardware used in this project.

Must Haves

Here is what the system absolutely needs to do. First, the IoT device must run when the internet is down, or when the network is down. Second, it needs timer-based watering, which includes support for sunrise and sunset. Third, it must allow for manual toggling of the watering state. Fourth, it needs the ability to back up and restore settings. Finally, there is a future goal: if it is sunrise or sunset but the temperature is too low, the system should still start watering, specifically to prevent the freezing of plant roots.

Wants

These are the nice-to-have features. First, the system should measure water time, humidity, and temperature, noting that all off-the-shelf sprinklers do this with various features. Second, it needs local network control with no data submitted to a third party. Third, it should offer graphing and the ability to analyze the data. Fourth, it needs watering runaway protection. Fifth, if the humidity is at a certain percentage, the system should skip watering for the day, which most over-the-shelf sprinklers do. Sixth, if the weather forecast says it is going to rain, the system should skip watering and notify me when this occurs; most off-the-shelf sprinklers can do this sort of thing. Seventh, I would like to send notifications to any platform I want, such as AWS, Gmail, IFTTT, or Alexa. And finally, I want to include a moisture sensor.

Hardware

At the lowest level, the IoT hardware should be able to do the following. First, it must toggle power on and off. Second, it should report the power state, humidity, and temperature. Third, it should not require an internet connection to function. And fourth, it needs to allow for customizing power toggling based on special conditions.

There is a twenty-dollar over-the-shelf Sonoff hardware option that does three of these four tasks easily. The fourth point, the customization, needs special programming. There are multiple options out there, but this fulfills the need for an "over-the-shelf" device that can be used with open-source software.

You can find the link to this specific Sonoff device on the blog post.

The easiest way to wire this up is using an existing extension cord. You cut into it and then follow the directions in the Sonoff wiring guide. You plug one end into the twenty-four volt AC power supply of an existing water sprinkler adapter. You can find the link to that power supply on the blog post.

However, here is the alternative hardware that I ended up using for my final build.

First, I used an ESP8266 microcontroller. This is a WiFi microcontroller that runs Tasmota. You can find the Amazon link for this on the blog post.

Second, I added an OLED screen. This serves as the status display for the sprinkler state. You can find the Amazon link for this on the blog post.

Third, I used a solid-state relay. This component switches the twenty-four volt AC sprinkler valve. You can find the Amazon link for this on the blog post.

And fourth, I included a BME280 sensor. This measures temperature, humidity, and pressure. It is used to skip watering when it is too cold or too humid. You can find the Amazon link for this on the blog post.

Software

The device can be flashed with open-source software called Tasmota. I prototyped with the Arduino IDE for a while, but Tasmota seems safer and has the features I needed. So, I won’t go into too much detail, but Tasmota solves the following problems. It is controlled on the local network. It runs even when the internet is down. It is highly customizable and has been battle-tested for years. It offers simple programming. And it provides multiple ways of interacting with the device, such as through the command line, MQTT, or a web interface.

There is a video on the blog post showing how to flash and set up the device when you get it. This is really common with this type of device.

Wiring and Module Parameters

Here is how the wiring maps out to the specific pins. Pin D2, which is GPIO 4, connects to the I2C SDA line. Pin D1, which is GPIO 5, connects to the I2C SCL line. Pin D5, which is GPIO 14, connects to Relay 1. And Pin D0, which is GPIO 16, connects to Counter 1.

Setup Time

Using the Tasmota Web Console command line, we need to set a few things up. First, we set the power on state to zero. This means that if there is a power outage or reset, the default power state is off.

Next, we set the time zone using the standard GMT offset. For example, if you are in Pacific Time, you would set the timezone to minus eight. Keep in mind that this does not account for daylight savings time. You can find the documentation link for this on the blog post.

Then, you should test your time by simply typing the word "time."

After that, you need to update your location. You can use a website like latlong.net to find your coordinates. You run a command for Latitude and replace the placeholder value with your actual latitude. Then you run a command for Longitude and replace the placeholder with your actual longitude. You can find the link to that coordinate finder on the blog post.

Finally, run the command "Status 7" to see the sunrise and sunset times in your local time. Ensure that this is the actual time in your location.

Setup Timers

Using the Tasmota Timer Web UI, four timers will be created. Two timers are for starting and stopping the watering at sunrise. Two timers are for the same at sunset.

The first timer, Timer 1, is enabled, in mode 1, set to zero zero zero zero, with no window, running every day, repeating, on output 1, with the action to turn on.

The second timer, Timer 2, is enabled, in mode 1, set to zero zero twenty zero, with no window, running every day, repeating, on output 1, with the action to turn off.

The third timer, Timer 3, is enabled, in mode 2, set to zero zero zero zero, with no window, running every day, repeating, on output 1, with the action to turn on.

The fourth timer, Timer 4, is enabled, in mode 2, set to zero zero twenty zero, with no window, running every day, repeating, on output 1, with the action to turn off.

Once these are entered, you turn the timers on. It is adjustable in the Web UI as well.

There is an image on the blog post showing the Sunrise Starting Timer configuration.

To stop the watering, Timer 3 has a twenty-minute offset. This allows for twenty minutes of watering. You do the same for Timer 4 for sunset. Per the Tasmota docs, when Mode 1 or Mode 2 is used, Latitude and Longitude become available. In that case, the Time value is always used as an offset, so make sure to set it to zero zero zero zero if no offset is wanted.

There is another image on the blog post showing the Sunrise Stopping Timer configuration.

Using the Tasmota Web Console command line, you can type in Timer 1, Timer 2, Timer 3, and Timer 4 to verify they are set correctly.

Runaway Protection

We have a few layers of safety. First, Timer 2 and Timer 4 should stop the sprinkler.

Second, the system never runs for more than one thousand three hundred twenty seconds, which is twenty-two minutes, when the power state is on. To do this, we use a rule. You enable a rule timer for that duration and increment a counter. Then, when that rule timer fires, it turns the power off. You can find the specific code for this rule on the blog post.

Third, you can use Node-RED to trigger a power state off if receiving specific MQTT messages. This could be adapted to turn off timers when the weather is expected to rain.

And finally, you can monitor on and off times using Grafana. I have prototyped using alerts with a Telegram integration in case all else fails.

Using the MQTT message for the sensor data, the data is formatted and sent to a local Grafana instance on a Raspberry Pi. Setup Rules (Optional)

Here are two more timers, or rules, that are still being developed. First, before sunrise, the system should check the temperature. If it is too cold, it should send an MQTT message and disable the start timers. Second, before sunrise, it should check the humidity. If it is raining, it should disable the timer.
