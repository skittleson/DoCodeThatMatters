Welcome to this guide on setting up a local first, cloud assisted smart home device. Specifically, we are looking at how to flash a NEO Coolcam Siren with a Temperature and Humidity Multisensor using Tasmota. The goal here is to get a local network first setup working.

First, let’s look at the components you will need. The main device is the NEO Coolcam Siren Multisensor, which is the hardware we are going to modify. You will also need a Serial-to-USB Adapter to connect the ESP8266 chip on the device to your computer for the flashing process. You can find the specific links for these items on the blog post if you need to purchase them.

Now, regarding the wiring and physical setup. This is a condensed guide on flashing with Tasmota. If you are completely new to this, the official documentation is a great place to start for a full getting started guide.

To flash this device, you will need to do some soldering directly onto the PCB. There is a plate in the back of the device that needs to be rotated to expose the battery holder. Once you have that open, go ahead and remove the three screws. The tricky part is making all the connections via soldering.

Here is the wiring map you need to follow. On the Neo Coolcam side, you have GPIO0, GND, TX, RX, and 3.3v. On the flasher side, which is your USB adapter, you have GND, GND, RX, TX, and 3.3v. So, you connect GPIO0 on the device to GND on the flasher. You connect GND on the device to GND on the flasher. You cross the serial lines: connect TX on the device to RX on the flasher, and RX on the device to TX on the flasher. Finally, you connect 3.3v on the device to 3.3v on the flasher.

I have included an image showing the soldering points, which depicts the specific locations on the circuit board where these connections are made. Another image shows the finalized soldering and how the device is wired to the flasher adapter.

It is important to note that GPIO0 must be connected to ground in order for the device to boot into flash mode.

Next, let’s talk about the flashing process itself. First, you need to install esptool. You can do this quickly using PyPi. The command to install it is simply pip install esptool.

Once that is installed, it is time to flash. You will need to identify your port and run a specific command in your terminal. This command works on Mac, Linux, or Windows as long as you are using PyPi. The command is esptool, specify your port (for example COM3), then write flash, set the flash size to 1 megabyte, set the flash mode to dout, and point to the tasmota-sensors.bin file.

There is an image here that shows the terminal output during the flashing process, confirming that the Neo Coolcam Multisensor is being flashed successfully.

If you prefer a graphical interface, there is an alternative tool called Tasmotizer that you can use instead of the command line.

After flashing, connect to the access point that the device creates to configure the default WiFi settings so it can connect to your local network.

Now, moving on to configuration. You need to apply a specific template. You can find this template on the blog post. The template code defines the device as a Neo Siren 3in1 and sets up the GPIO mappings.

Here are the Tasmota Console Commands you need to run to get everything working. I will walk you through each one and why it is used.

First, run a backlog command that sets Option 65 to 1 and Option 66 to 1, and sets the module to 54. This enables fast power cycling and registers the device as a Tuya module.

Second, run TuyaMCU with arguments 11 and 104. This maps the alarm siren and LED to a toggle switch.

Third, run TuyaMCU with arguments 71 and 105. This maps the indoor temperature sensor.

Fourth, run TuyaMCU with arguments 73 and 106. This maps the indoor humidity sensor.

Fifth, run TempRes 1. This adjusts the temperature resolution so that instead of showing a raw value like 291, it displays it as 29.1 degrees.

Sixth, run TuyaSend2 with arguments 113 and 0. This disables the built-in temperature alarm. We want to handle alarms with a rule instead.

Seventh, run TuyaSend2 with arguments 114 and 0. This disables the built-in humidity alarm, again allowing us to use our own rules.

All of this assumes that you have MQTT configured. The temperature and humidity data will not show up unless this is set up. If you ever want to undo the Tuya specific settings, you can use the command SetOption66 0. It is also optional but recommended to ensure the dpId states are set by running TuyaSend0.

Now that everything is hooked up, the data will be polled and reported every so often. The caveat is that it is not always temperature and humidity data; you must account for this in your logic later.

Here is an example of what the MQTT log looks like. It shows a timestamp and a JSON payload containing the time, the Tuya SNS data with temperature at 28.5 and humidity at 4.3, and the temperature unit set to Celsius.

There is a screenshot of the Tasmota Web UI here. It shows the Tuya temperature, humidity, and the siren LED power toggle, confirming that the configuration was successful.

I have also considered using rules to catch the Tuya event and then publish the MQTT message in that rule.

Moving on to Node-RED and other smart logic. You should set up an MQTT node in Node-RED. The topic should be tele/tasmota_replace_with_id/sensor. You need to replace the ID part with the actual MQTT ID from the Tasmota information screen. You can find this under Information and then MQTT Full Topic.

Next, add a function node that can handle cases where the temperature or humidity might be undefined. It is optional, but you can add metadata such as a measurement tag for use with Grafana.

Here is the logic for that function node. It sets the measurement variable to siren-tv. It tries to parse the JSON payload. If it finds TuyaSNS data, it creates a new payload object. If there is a temperature, it copies that value over. If there is a humidity, it copies that value over but multiplies it by 10. If there is an error, it logs that it was unable to get the temp and humidity.

To turn on the siren remotely, you simply send either ON or OFF to the MQTT topic cmnd/tasmota_replace_with_id/POWER. You will receive a return MQTT message on the topic stat/tasmota_replace_with_id/POWER to confirm the action.
